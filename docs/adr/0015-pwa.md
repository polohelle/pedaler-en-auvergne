# 0015 — Application web installable et consultation hors connexion

- Statut : acceptée
- Date : 2026-10-14

## Contexte

Le portail doit s'installer sur l'écran d'accueil (Android, iPhone) et rester consultable
hors connexion pour l'agenda, l'annuaire et les actualités ; la carte reste en ligne. Le
cahier des charges désigne `@vite-pwa/astro`, dont la version 1.2.0 ne déclare la
compatibilité que jusqu'à Astro 5, alors que le site est en Astro 7.

## Décision

- **`@vite-pwa/astro` 1.2.0 avec `vite-plugin-pwa` 1.3.0** (qui supporte Vite 8). Essayé
  comme convenu : la build produit `sw.js`, le manifeste et le script d'enregistrement, et les
  tests le prouvent. L'écart de dépendance pair est déclaré explicitement
  (`pnpm.peerDependencyRules` dans `package.json`). Le repli prévu, Workbox lancé après le
  build, n'a pas été nécessaire.
- **Manifeste** : nom, nom court, langue, couleurs du site, icônes 64, 192, 512 et masquable,
  générées depuis `public/favicon.svg` par `pnpm icones` et versionnées.
- **Service worker** (Workbox, `generateSW`, mise à jour automatique à chaque publication) :
  - précache des styles et scripts, des icônes et des pages de premier niveau (accueil,
    annuaire, agenda, actus, association, mentions légales, page « hors connexion ») ;
  - les fiches ne sont pas précachées, pour que l'installation reste légère quand l'annuaire
    grandira : elles passent par un cache « réseau d'abord » (200 pages, 30 jours), donc
    restent disponibles une fois consultées ;
  - une page jamais ouverte, hors connexion, mène à `/hors-ligne/` ;
  - pas de repli global façon application monopage.
- **Enregistrement** par un fichier séparé (`registerSW.js`), compatible avec la CSP.

## Conséquences

- Tests : le précache des pages HTML est vérifié dans `sw.js`, et le parcours hors connexion
  est rejoué dans Chromium (`tests/e2e/pwa.spec.ts`).
- À surveiller : une version de `@vite-pwa/astro` qui supporte officiellement Astro 7
  permettra de retirer la règle de dépendance pair ; si une mise à jour d'Astro casse
  l'intégration, le repli Workbox après le build reste la solution.
- Le bandeau d'invitation à installer (et le mini-guide iPhone) demande un peu de
  JavaScript ; il est prévu avec le lancement public (phase 2).
